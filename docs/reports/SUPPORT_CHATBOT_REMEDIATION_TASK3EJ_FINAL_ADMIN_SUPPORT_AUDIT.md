## 3. Audit of Historical Subject Extraction (`AdminSupportPage.tsx`)

### 3.1 Targeted Detection (`isGenericSubject`)
```ts
function isGenericSubject(subject: string): boolean {
  if (!subject) return true;
  const s = subject.trim().toLowerCase();
  return (
    s === "marketplace question" ||
    s === "chatbot inquiry: marketplace question" ||
    s === "support request" ||
    s === "chatbot inquiry: support request" ||
    s === "chatbot inquiry:"
  );
}
```
- **Audit:** Only matches known legacy placeholders produced by earlier versions of `FloatingChatbot.tsx`. Any real, meaningful subject entered by users (e.g. `"Payment not releasing for milestone"`) evaluates to `false` and is displayed directly without modification.

### 3.2 Safe Fallback & Extraction (`getDisplaySubject`)
- **Audit Findings:**
  1. **Structured Header Parsing:** Matches `--- User Inquiry ---\s*\n([\s\S]*?)(?=\n---|\n===|$)`, extracting exclusively the user's initial inquiry text generated by `buildTicketDescription()`. It will **never extract administrator replies or system headers**.
  2. **Truncation & Summarization:** Normalized with `.replace(/\s+/g, " ")` and bounded to 80 characters (`summary.slice(0, 77) + "..."`) for table display.
  3. **Original Subject Visibility:** Returns `originalSubject: ticket.subject`. When generic, rendered as an explicit secondary italic subtitle: `<div className="text-[11px] text-amber-700 italic">Stored Subject: {display.originalSubject}</div>`.
  4. **Database Immutability:** Pure UI rendering function. The MongoDB record and API response remain completely unaltered.
  5. **XSS & Injection Safety:** Rendered exclusively as React JSX text `{display.title}` and `{display.originalSubject}`, which automatically HTML-encodes all output. No `dangerouslySetInnerHTML` is used.
  6. **Safe Fallbacks:** If the description is empty, missing, or malformed, falls back to the first non-header line, or `ticket.subject`, or `"Support Inquiry"`.

## 5. Audit of Admin Reply Functionality

Traced the complete reply execution path:
1. **Frontend Form Submission (`AdminSupportPage.tsx`):**
   - Disables submit button during flight via `submittingReply` state to prevent duplicate submissions.
   - Requires non-empty message: `if (!selectedTicket || !replyText.trim()) return`.
   - Calls `supportApi.addReply(selectedTicket._id, { message: replyText })`.
2. **API Call (`operations.api.ts`):**
   - Calls `POST /support/${id}/reply`.
   - Axios interceptor injects `Authorization: Bearer <token>` and `X-Request-ID`.
3. **Backend Route & Controller (`supportTicket.routes.ts` & `supportTicket.controller.ts`):**
   - Guarded by `authenticate`.
   - Validates `id` as MongoId and `message` between 1 and 3000 characters via `replyTicketValidation`.
4. **Backend Service (`supportTicket.service.ts`):**
   - Checks `isOwner` or `isAdmin` (`role === "admin"`).
   - Rejects closed tickets with `400 Bad Request: "Cannot reply to a closed ticket"`.
   - Automatically sets `authorRole: "admin"` and transitions `status` to `waiting_for_user`.
   - Creates in-app notification for the user.
5. **UI Post-Submission Handling:**
   - Clears `replyText` on success.
   - Refreshes ticket details and list via `supportApi.getTicketById` and `loadTickets()`.
   - Displays `toast.success("Support reply posted successfully.")`.
   - Catches and displays API error messages via `toast.error(...)`.
